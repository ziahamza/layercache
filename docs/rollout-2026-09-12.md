# Four-project rollout, 2026-09-12

Layer Cache is public under MIT. All four consumer changes are merged on main
and use `ziahamza/layercache/action/turbo@main`. No actions mirror, custom consumer
authentication script, new consumer package, or long-lived CI cache secret is
required. Main intentionally tracks current action code until versioning exists.

## Shared service and trust

All four projects use `https://layer-cache.ziahamza.com`, with independent
PostgreSQL databases, S3 buckets, credentials, and 5 GiB project quotas. A live
four-project test wrote/restored distinct 128 MiB payloads under the same native
key, verified every digest, and denied cross-project selectors. Existing signed
Actions downloads and a 128 MiB registry blob also passed.

Turbo/registry OIDC write tokens require the configured default ref and a signed
push, workflow_dispatch, or schedule event. Other refs/events receive read-only
tokens. The server verifies GitHub signatures, issuer, expiry, audience, and
repository. PR step conditions alone are not the trust boundary. Project members
and the service operator remain trusted writers. Regression coverage exercises
both integrations across three refs and seven event states, including missing
event claims and pull_request_target.

## Failures found during qualification

An earlier Agent Access reuse attempt missed while the host had only 46 GiB free,
below its configured 60 GiB reserve. The same run passed unchanged after space
recovered. The reserve was not lowered.

Concurrent Parle CI exposed six gateway out-of-memory restarts under its 2 GiB
container limit. Caddy returned 502 while the process was down. The initial
qualification restored only 46 of 49 tasks and correctly failed. A later quiet
run passed, but that alone did not resolve the concurrency defect.

The real S3 SDK regression test reproduced a 553,648,128-byte allocation for one
unknown-length upload, even with a 5 GiB admission limit. The fix sets the part
size from that limit, normally 16 MiB, and shares a 256 MiB staging-buffer budget
across all projects. Larger S3 parts run alone. Canceled admission returns before
allocating a buffer or contacting S3. The container also sets GOMEMLIMIT=1GiB.

The fix is committed in `2b1879d` and deployed as image
`sha256:f5ae59915173ae6af0655815fb9a6907296ad41c19e6b79e15d2d63c21317c72`.
The real-SDK regression went from 553,648,128 bytes to a passing 16 MiB bound.
The live follow-up wrote 64 unique artifacts concurrently across all four
projects, verified all 64 restores in 1.885 seconds, and observed zero gateway
restarts. Memory usage after the burst was about 386 MiB. Fixture bytes remain
subject to ordinary project quotas and eviction, not permanent pins.

Four-project 128 MiB multipart writes/restores and cross-project denial checks
also passed again against the fixed image. No gateway restart occurred during
these checks or the subsequent parallel GitHub qualification runs.

## Remaining work

- Docker registry total-capacity limits and tagged-layer retention remain
  unfinished. Routine Docker CI writers are not enabled by this rollout.
- Public Builds are not deployed and are not required for these Team Cache hits.
- Layer Cache's action bundle/typechecking and performance CI passed, but its
  full native Go CI still reports existing platform/fixture failures, including
  inherited GITHUB_REF and macOS canonical-path/case-sensitive assumptions.
  Local full Go tests, server/CLI race tests, and vet passed for the gateway
  rollout. This is not a claim that every Layer Cache CI job is green.
- No secret-content inspection or history audit was performed in this pass.
